EL-UC-001 � Apply for Leave
Primary Actor
Employee
Supporting Actors / Systems
Academic Calendar service (for VL vacation-period data); Substitute interaction is handled by EL-UC-002 when required.
Goal / Description
Create and submit a valid new leave application and place it into the applicable processing path.
Trigger
Employee needs to request CL, RH, SCL, EL, COL, or VL.
Preconditions
� Employee is authenticated and authorized for own leave activity.
� Current configured leave policy/hierarchy is available; effective published holiday/RH calendar is available; Academic Calendar vacation-period data is available where VL is requested.
UC Type
Actor-triggered

Main Success Scenario
M1. Employee starts a new leave application.
M2. Employee selects the leave category and requested period and enters purpose/reason and other required information.
M3. System captures Station Leave details in the same application when applicable.
M4. System validates category eligibility, entitlement/balance, counting/calendar conditions, and impermissible overlap.
M5. When responsibility coverage is required, Employee nominates one eligible substitute.
M6. Employee submits the application.
M7. If substitute consent is required, System places the request in Awaiting Substitute Response; otherwise it routes the request to Unit Head review. A Director-applicant follows the self-sanction path.
Alternative / Exception Flows
A1 Validation fails: identify the failed condition and do not allow progression.
A2 Substitute nomination invalid: reject the nominee and allow another eligible nominee.
A3 After a substitute decline, the Employee may invoke EL-UC-019 to nominate a replacement or EL-UC-007 to withdraw.
Success Postcondition
A valid submitted request exists in the correct next processing state.
Failure / Minimal Guarantee
No invalid request is allowed to progress; previously entered data may remain available as implementation permits.

EL-UC-002 � Respond to Substitute Request
Primary Actor
Substitute / Responsibility Holder
Supporting Actors / Systems
Employee
Goal / Description
Accept or decline a nominated responsibility assignment.
Trigger
A substitute responsibility request is assigned to the nominated employee.
Preconditions
� The nominee is an eligible substitute for the responsibility period.
� The associated leave/extension request is awaiting substitute response.
UC Type
Actor-triggered

Main Success Scenario
M1. Substitute opens the assigned responsibility request.
M2. System presents the applicant, responsibility period, and relevant request context.
M3. Substitute selects Accept or Decline.
M4. System records the response.
M5. If Accept, the consent gate is released and the request proceeds to Unit Head review; if Decline, the request becomes Applicant Action Required.
Alternative / Exception Flows
A1 If the request is no longer pending, System prevents a stale response.
Success Postcondition
The substitute response is recorded and the request enters the outcome-appropriate state.
Failure / Minimal Guarantee
No routing occurs without a valid recorded response.

EL-UC-003 � Review Leave-Related Request at Unit Head
Primary Actor
Unit Head
Supporting Actors / Systems
Employee; Establishment / final Sanctioning Authority as downstream roles
Goal / Description
Review a routed new-leave, cancellation, or extension request and record the decision/recommendation permitted by the applicable policy.
Trigger
A request enters the Unit Head work queue.
Preconditions
� The request has passed applicable submission/consent gates.
� The Unit Head is the resolved Unit Head for the applicant.
UC Type
Actor-triggered

Main Success Scenario
M1. Unit Head opens the assigned request and reviews the request context and available supporting information.
M2. For a new CL/RH request, Unit Head records final Approve or Reject.
M3. For higher-sanction new leave, cancellation of higher-sanction leave, or EL/COL/VL extension, Unit Head records Recommended or Not Recommended.
M4. System records the outcome.
M5. A Unit-Head-final outcome completes the decision; a recommendation outcome continues through the configured higher-sanction path.
Alternative / Exception Flows
A1 Director-applicant cases do not use the normal Unit Head path.
A2 Not Recommended for higher-sanction contexts is not a final rejection.
Success Postcondition
The Unit Head outcome is recorded and the request is either finally decided or advanced to the configured next stage.
Failure / Minimal Guarantee
No unauthorized or out-of-scope decision is recorded.

EL-UC-005 � Make Final Sanctioning Decision
Primary Actor
Sanctioning Authority (Deputy Registrar (Estt.), Dean, Registrar, Director, or other configured competent authority)
Supporting Actors / Systems
Employee; Unit Head; Establishment where configured
Goal / Description
Record the final approve/reject decision for a routed higher-sanction new-leave, cancellation, or extension request.
Trigger
A request is assigned to the resolved final Sanctioning Authority.
Preconditions
� The actor is the resolved competent final authority for the request.
� Required upstream routing and consent gates have been completed.
UC Type
Actor-triggered

Main Success Scenario
M1. Authority opens the assigned request and reviews the request, recommendation, and available evidence.
M2. Authority records Approve or Reject.
M3. System records the final decision and notifies the employee.
M4. For new-leave approval, System updates the leave record/account.
M5. For cancellation approval, System marks the leave Cancelled and restores/adjusts deducted balance; cancellation rejection preserves the original approval.
M6. For extension approval, System posts only the incremental additional period; extension rejection preserves the original approved leave.
Alternative / Exception Flows
A1 SCL purpose admissibility is decided by the applicable Sanctioning Authority; no separate encoded admissibility criterion is required.
A2 Director-as-applicant uses the Director-specific self-sanction path.
Success Postcondition
A final decision and the context-appropriate completion effects are recorded.
Failure / Minimal Guarantee
No final decision is recorded by an unauthorized authority.

EL-UC-021 � Process SLA Threshold Event
UC Type
Event-triggered
Primary Actor
N.A. � Event-triggered
Supporting Actors / Systems
Responsible user; configured higher/responsible authority as notification/escalation recipient where applicable
Goal / Description
Process a configured SLA reminder or escalation threshold for an actionable workflow task.
Trigger
Configured reminder or escalation threshold reached for an actionable workflow task.
Preconditions
The task is SLA-controlled and the applicable reminder/escalation thresholds are configured.
Main Success Scenario
1. System identifies the task and threshold event.
2. System checks whether the task is still pending.
3. At a reminder threshold, if still pending, System reminds the responsible user and logs the reminder.
4. At an escalation threshold, if still pending, System performs the configured escalation action (notification and, where configured, routing/responsibility change) and logs the escalation.
5. If the task is no longer pending, System issues no corresponding reminder/escalation.
Alternative / Exception Flows
Notification-only escalation does not create a workflow transition. Where configured escalation changes routing/responsibility, that automatic System transition is represented cross-cuttingly in the applicable workflow.
Success Postcondition
