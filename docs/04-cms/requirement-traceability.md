# CMS requirement traceability

Source: synchronized CMS_DOCS v1.3 artifacts. This matrix records implementation and automated evidence as present in the repository; deployment evidence is separate. Test names indicate representative coverage and do not imply that every boundary has a dedicated test. Status notes preserve policy decisions and open spec issues.

## Coverage summary

- 14 CFR, 73 AFR, 22 UC, 41 active BR, 1 retired BR, 8 basis workflows, and 3 composite workflows are inventoried below.
- Implementation coverage is present across backend services/models/APIs and the CMS client routes. Specific security/edge-case gaps are identified rather than hidden in the deployment note.
- Open domain clarifications: ISS-CMS-007 (no defined transition into In Progress), ISS-CMS-008 (approved reopen status unspecified), ISS-CMS-009 (assignment target semantics unspecified), ISS-CMS-010 (non-verification closure unspecified). Configurable policy defaults are documented in the CMS README.

## Verification scope and remaining evidence gaps

- The automated CMS backend suite exercises domain transitions, authorization/ownership, core lifecycle, closure, rejection, reopening, notification-event creation, and SLA idempotency. Static checks cover module boundaries, permission manifest, migration drift, and navigation-route parity.
- API tests cover worklist filtering, escalation/feedback/announcement/report access, CSV export, role reassignment, and attachment upload/download plus an invalid extension. Browser-level end-to-end journeys and every attachment size/count edge case remain untested.
- A PostgreSQL-backed local startup/migration was not verifiable on this machine because Docker, PostgreSQL client/server, and a listener on 5432 are unavailable. SQLite syncdb-based tests are not equivalent to PostgreSQL migration verification.
- Email delivery is intentionally outside CMS: CMS commits notification trigger events for a platform delivery service. SLA values and attachment constraints are environment-configurable; SLA processing is inert until durations are configured.
