# How the ELM module was built (Assignment 6 / 6B)

## Tools
- **Code generation and repair:** Qwen2.5-Coder-7B-Instruct (Q4_K_M), run locally with Ollama
  0.34 and driven through aider 0.86. No cloud model generated module code.
- **Orchestration and verification:** Claude (Claude Code) prepared prompts and context for the
  local model, ran the build, tests, linters and live end-to-end checks, and diagnosed failures.
- **Non-AI tools:** pytest, ruff, import-linter, drf-spectacular, tsc, vitest, Django checks.

## Phase 1 (git tag `phase1-elm`)
All module code was generated by the local model from the ELM v1.4 specification.
Only the integration corrections the assignment allows were made by hand: module and route
registration, missing imports and interface names, and DRF keyword names.

## Phase 2 (branch `module/leave-phase2`)
- **Review:** the local model reviewed each file against the BR-EL rules (aider ask mode).
- **Tests:** the local model wrote the test suites (43 ELM tests). Some generated tests were wrong
  and were corrected after diagnosis.
- **Fixes:** most defects were fixed by prompting the local model with the failing test and the
  rule, then re-running the tests to verify.
- **Hand edits:** where the model's fix was incomplete, failed to compile, or regressed other
  code, the change was made by hand. These are marked "manual" in the issue log. The largest is
  the frontend: `client/src/modules/leave/api/hooks.ts` and the three pages were completed by hand
  on the model's layout after three repair rounds did not type-check.

Every defect, how it was found, who fixed it (model or manual), and how it was verified is listed
in the Phase-2 issue log kept with the submission (`phase2-issues.md`).
