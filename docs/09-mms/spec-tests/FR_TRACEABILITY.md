# FR requirement traceability

This matrix links each FR case in the current draft design to behavioral assertions in the current test suite. The designs are not frozen: they were prepared after code inspection and have not been committed. A linked test may fail; the status reflects the latest isolated SQLite reproduction. `PARTIAL` means the tests cover only part of a rolled-up CFR. `NOT AUTOMATED` records a missing contract or external input rather than inventing one. The FR suite includes `test_linked_behavior.py`, which parameterizes 65 FR IDs to re-execute mapped UC/BR assertion bodies under FR test IDs and source IDs; it reuses those implementations rather than independently translating every FR case. The repository ZIP omitted authoritative source PDFs; the synchronized Problem Statement v1.0 and CFR/AFR registry v1.4 PDFs were found in Downloads and used to check source identifiers and expectations. The design/test provenance still does not meet the fresh-session/freeze sequence because the designs were prepared after code inspection.
