4. Implementation Architecture

4.1 Layering & Separation of Concerns

  • Pure Domain Logic (modules/elm/domain/): Zero Django/ORM dependencies. leave_policy.py calculates continuous vs. non-continuous calendar days, rollover (2 VL : 1 EL), and overlap intervals. state_machine.py implements a declarative state transition table mirroring CW-EL-01 through CW-EL-04.
  • Data Layer (modules/elm/models/ & migrations/): Models with explicit DB constraints, indexing on (user_id, status), and integer user IDs (ADR-0013).
  • Service Layer (modules/elm/services/): Atomic transactional functions (leave_service.py and balances.py) orchestrating state transitions, balance updates, and audit trail insertions.
  • Selectors (modules/elm/selectors/): Fail-closed querysets scoping records by caller role (e.g. visible_leave_requests, pending_approvals).
  • REST API (modules/elm/api/): Endpoints mounted at /api/v1/elm/ enforcing HasModuleGrant("elm") and granular permissions.
  • Frontend (client/src/modules/elm/): Full React/Mantine client interface featuring Apply Leave, My Leaves, Balance Overview, Substitute Approvals, Administrative Offline Recording, and Holiday Calendar views.
