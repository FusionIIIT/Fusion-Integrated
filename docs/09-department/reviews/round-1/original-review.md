### Majors

**R1-03 · Architecture · Timetable overlap has no database enforcement.** Review §3.2 says “Invariants that must hold under concurrency are database constraints, not Python checks.” The regular upload and replace paths use a shared DepartmentDetails lock and an overlap query (`modules/department/administration.py:27–63`), but `modules/department/models.py:196` only constrains day and duration. BR-DEPT-010, Business Rule Specifications, line 219, says “A timetable update must not be saved or advanced for approval when overlapping slots are detected.” Close when persistence enforces the approved overlap rule and accepted conflict-free writes still work. The current department lock is real and this finding does not claim a demonstrated race in the normal service paths.

**R1-04 · Security · Write views have no throttle scope.** Build prompt Step 7.7 says “Every write endpoint carries a `throttle_scope`.” `rg -n 'throttle_scope' modules/department` returns no matches while `config/settings/base.py:210–213` documents scope opt-in. Close when all write endpoints declare the appropriate configured scope and refusal coverage verifies that it applies.

**R1-05 · Spec fidelity · Programme information is reduced to the student's affiliation and omits its unavailable state.** AFR-DEPT-036, Requirement Registry, line 563, says “The system shall allow Students to view department academic program information.” UC-DEPT-018, Use Case Specifications, line 568, says “No applicable timetable/program data is published: system shows an empty/unavailable state.” The academic-context response at `modules/department/api/administration.py:98–112` supplies only programme name and batch. `client/src/modules/department/TimetablePage.tsx:105–112` silently omits that display when none is returned and has no academic-context error feedback. `modules/department/tests/test_workflows.py:129–131` only asserts those two values and the cohort timetable. The quality report calls the reduction a dependency without recording the corresponding written decision at line 36. Close with agreed programme content and its unavailable state or explicit acceptance of a reduced scope. The baseline leaves the exact programme fields open.

**R1-06 · Spec fidelity · Traceability overstates test coverage.** Review §3.1 says “Every live id is cited by at least one test.” Literal extraction from `modules/department/tests` gives 9 of 22 BRs, 9 of 20 UCs and 4 of 12 WFs. Several IDs occur only as abbreviated suffixes in grouped docstrings. Test behavior is also missing for some obligations. For example, BR-DEPT-003 at Business Rule Specifications line 138 says “Block publication when required content/target information is missing or invalid.” Its citation in `test_workflows.py:39–54` tests only a valid publication. The stock flow at lines 57–80 cites recipient notifications but only counts final Faculty notice rows. It does not assert the new-request notification for Dept_Admin or HOD, required by AFR-DEPT-041 and AFR-DEPT-042. Close with every live ID traceable to an assertion of its required behavior, accounting explicitly for accepted gaps.

**R1-07 · Security · Refusal evidence is incomplete.** Review §3.4 states “Every endpoint refuses a principal without the module grant, and refuses a principal with the grant but without the permission. These are two separate refusals.” Dedicated tests at `modules/department/tests/test_announcements.py:58–66` exercise those cases only for announcement reads, and the Department tests provide no cookie-authenticated write refusal without the CSRF header. The `DepartmentAccessView` at `modules/department/api/common.py:55–60` checks a module grant alone, whereas Step 7.7 says “Every view sits behind both gates — the module grant, then the permission.” That endpoint returns the caller's own effective permission metadata; I found no cross-user data exposure there. The report's shared-navigation gap also needs a specific decision. IAM already emits role-specific navigation and module grants (`Backend/backend/iam/services.py:279–305`), while Fusion-Integrated retains the union (`fusion_auth/client.py:153–157`, `fusion_auth/views.py:112–120`). Close with named access-endpoint contract or approval, scope-focused and cookie-CSRF regression tests and acting-role shell behavior agreed with the approver.
