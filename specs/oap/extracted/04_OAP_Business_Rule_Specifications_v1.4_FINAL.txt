Rule ID | OA-BR-31
Rule Name | No-Dues Domain-Specific Verification
Rule Type | Authorization
Rule Statement | Each of the seven mandatory no-dues authorities may record clearance only for its own institutional domain.
Applies To | No-dues verification
Condition / Trigger | Authority opens a clearance request
Required Outcome / Constraint | Library→Librarian; Hostel→Hostel Warden; Mess→Mess In-charge; respective Department→authorized Department verifier; Lab→Lab Supervisor; Academic Section→authorized Academic Section verifier; Student Section→authorized Student Section verifier.
Exceptions / Exclusions | None. All seven domains are mandatory for every student in this baseline.
Source / Rationale | PS 2.6, 3.3

Rule ID | OA-BR-42
Rule Name | Dual Supervisor Verification
Rule Type | Authorization / Completion Guard
Rule Statement | An assistantship claim requires verification in both the assigned Thesis Supervisor role and the assigned TA Supervisor role before Department Administrator review.
Applies To | Assistantship claims
Condition / Trigger | Supervisor verification
Required Outcome / Constraint | Record both role-verifications. The roles may be held by the same faculty member or by different faculty members; no order is prescribed between them.
Exceptions / Exclusions | One supervisor-role verification does not replace the other required role-verification.
Source / Rationale | PS 3.4; instructor clarification 2026-08-23

Rule ID | OA-BR-46
Rule Name | Assistantship Processing Sequence
Rule Type | Routing
Rule Statement | The accepted assistantship progression is: both Thesis Supervisor and TA Supervisor verifications (in either order) → Department Administrator review/forward → HoD decision → Academic Administrator stipend processing for approved claims.
Applies To | Assistantship claims
Condition / Trigger | Claim progresses after submission
Required Outcome / Constraint | Do not bypass either required supervisor-role verification or the subsequent specified actor sequence.
Exceptions / Exclusions | No withdrawal, send-back, or supervisor/Dept Admin rejection path is established by the PS.
Source / Rationale | PS 3.4

Rule ID | OA-BR-51
Rule Name | Departmental Assignment Authority
Rule Type | Authorization / Source
Rule Statement | The Department Administrator records thesis-supervisor assignments and TA assignments based on departmental decisions; a TA assignment associates a PG student with a course/subject, a faculty member, or both.
Applies To | Supervisor/TA assignments
Condition / Trigger | Department decision available
Required Outcome / Constraint | Record the departmental thesis-supervisor assignment and record each TA assignment with the course/subject and/or faculty target specified by the departmental decision.
Exceptions / Exclusions | No seminar-specific TA assignment semantics are assumed.
Source / Rationale | PS 2.5, 3.5; instructor clarification 2026-08-23

Rule ID | OA-BR-52
Rule Name | Thesis and TA Supervisor Role Distinction
Rule Type | Role / Eligibility
Rule Statement | Thesis Supervisor and TA Supervisor are distinct assistantship-verification roles, although the same faculty member may hold both roles for a student.
Applies To | Assistantship supervision
Condition / Trigger | Supervisor verification
Required Outcome / Constraint | Resolve both roles for the claimant and require both role-verifications before department review.
Exceptions / Exclusions | The specification does not require the two roles to be held by different persons.
Source / Rationale | Instructor clarification 2026-08-23
