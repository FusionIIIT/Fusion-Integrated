[Title] LMS (Course Management)
Use Case Specifications — Version 1.0
SYNCHRONIZED DRAFT — open PS questions retained
[Heading 1] 1. Scope and conventions
These Use Cases are derived only from LMS (Course Management) Problem Statement v1.0. Actor-triggered and event-triggered services use one common UC formalism. The LMS system is not its own UC actor. Unresolved late-submission, resubmission, notification, TA-permission, Observer-linkage, and post-release-grade-change matters remain explicit issues rather than invented behavior.

[Heading 2] UC-LMS-001 — Access Course Workspace
--- TABLE ---
UC Type | Actor-triggered
Primary Actor | Student / Faculty / TA / Observer (role-specific authorized course user)
Supporting Actors / Systems | Existing course-registration/association data source
Goal / Description | Open the dedicated workspace for a course the user is authorized to access and view course-home information.
Trigger | User selects a course from Fusion.
Preconditions | Course exists; user is enrolled in, assigned to, or linked to the course according to available source data.
Success Postcondition | Authorized user views the course home.
Failure / Minimal Guarantee | No unauthorized course content is exposed.
Related Business Rules | BR-LMS-001, BR-LMS-002, BR-LMS-003, BR-LMS-004
Related CFRs | 
Related Workflow(s) | N/A
--- END TABLE ---
[Heading 3] Main Success Scenario
[List Bullet] 1. System identifies the selected course and requesting user.
[List Bullet] 2. System validates course-specific access.
[List Bullet] 3. System opens the dedicated course workspace.
[List Bullet] 4. System displays syllabus, schedule, instructor(s), and TA(s).
[Heading 3] Alternative Flows
[List Bullet] If access is not authorized for the selected course, access is denied.
[Heading 3] Exception Flows
[List Bullet] If authoritative registration/link data are unavailable, the system cannot confirm access and shall not expose the workspace.

[Heading 2] UC-LMS-015 — Process Scheduled Content Release
--- TABLE ---
UC Type | Event-triggered
Primary Actor | N.A. — Event-triggered
Supporting Actors / Systems | N/A
Goal / Description | Make scheduled course material or an assignment available when its configured release time is reached.
Trigger | Configured future release date/time for a scheduled material or published assignment is reached.
Preconditions | Content is in Scheduled state and remains valid for publication.
Success Postcondition | Scheduled content becomes Published/Available.
Failure / Minimal Guarantee | Content is not exposed prematurely.
Related Business Rules | BR-LMS-005, BR-LMS-006, BR-LMS-011
Related CFRs | 
Related Workflow(s) | BW-LMS-01, BW-LMS-03; CW-LMS-01
--- END TABLE ---
[Heading 3] Main Success Scenario
[List Bullet] 1. System identifies scheduled content whose release time has been reached.
[List Bullet] 2. System verifies the content is still eligible for release.
[List Bullet] 3. System changes the content state to Published/Available.
[List Bullet] 4. System makes the content visible to the authorized audience.
[Heading 3] Alternative Flows
[List Bullet] If scheduled content was withdrawn/unpublished before release, no release occurs.
[Heading 3] Exception Flows
[List Bullet] If release processing fails, content remains unavailable and the failure is recorded for operational handling.
